# Plan: Issue #85 — Reinstate the whole-page custom template: one file for the full design, plus autodetection

## Goal

A whole-page custom page-template source is a first-class form again on all three entry points: `render(page_template_source=…)` on the API, `--page-template <file>` on the CLI, and autodetection of `<data-stem>.tex.jinja` next to the data file / `page_template.tex.jinja` in cwd. One file owns both page-template slots (header and footer chrome); document-level settings (`font`, `header_font`, `diff_style`, `margins`) keep applying alongside it, matching how they already apply alongside per-slot sources. A recipe's own document content — faktura's top-level `footer` — keeps its precedence over the footer slot, exactly as it has today over a custom `footer_source`.

## Approach

### State verified before planning

- The capability existed through v0.16.0 and was removed in `a986661` (#80). The pre-removal implementation is fully recoverable at commit `154e474` (v0.16.0): `load_page_template(page_template_source=…)` built `SlotSpec(source=src)` for the header and `SlotSpec(source=src, shared_source=True)` for the footer, and `_page_template.tex.jinja` guarded the footer arm with `if not page_template.footer.shared_source` so the shared source was emitted exactly once. `render()` rejected combining `page_template_source` with `header_source`/`footer_source` (`ValueError`). The CLI had `_autodetect_page_template()` (sibling `<stem>.tex.jinja`, then `./page_template.tex.jinja`), an explicit `--page-template` that won over autodetection, a conflict error against the slot flags, slot flags suppressing autodetection, `asset_dir` = the template file's resolved parent, and a `Using page template: <path>` stderr notice on autodetect.
- The current code carries everything the custom-source path needs per slot: `SlotSpec.is_custom`, the custom arms in `klartex/templates/_page_template.tex.jinja`, `header_reclaim` returning empty for a custom header, `_check_margin_top` skipping custom headers, and the first-page plain style suppressed for a custom header. What is missing is only the "one source owns both slots, emitted once" wiring and the CLI/API/autodetect surface.
- Since the removal, the slot model gained `margins` (`margin_setup`, emitted in step 1 of the composition — before both slots, deliberately so a custom source's own `\geometry` wins; #65/#89) and font values became `str | dict` (file-form fonts preflighted via `font_files()` against the asset root; #92). Both are document-level settings, orthogonal to which chrome form is in use; nothing about them needs to change, but the reinstated mode must not bypass them.
- Recipe-level footer precedence is decided in `klartex/templates/_recipe_base.tex.jinja` (lines 13–17): a top-level `data.footer` is emitted **after** the page-template composition "so it wins over the footer slot, predefined or custom", via `emit_kxfooter(data.footer, page_template.page_numbers)`. So even with a fully custom footer slot, faktura's footer renders and `page_template.page_numbers` reaches it. The whole-page mode inherits this for free — but it means `page_numbers` is *not* inert in whole-page mode on the recipe path.
- The composition template inserts a custom source verbatim (`\VAR{…source}` in the outer Jinja render — the source's own text is not re-parsed as Jinja). That was also v0.16.0's behavior; the `.tex.jinja` naming is conventional. The user's real-world template (brand colors, geometry, `\setmainfont`) is plain LaTeX and works verbatim.
- `render()` schema-validates the whole payload before `load_page_template()` runs, so the payload's `header`/`footer` remain schema-validated even when a whole-page source shadows them for composition — same as for `header_source`/`footer_source` today.
- The server (`klartex/server/render.py`, added in #81 after the removal) has never had a whole-page field. Its `RenderRequest` carries `header_source`/`footer_source` with per-source size and encodability checks; a core `ValueError` already maps to `400 input_error`, an oversized source field returns 400 (`413` is reserved for the request's Content-Length, checked in `app.py`), and `asset_dir` is set to the request tempdir whenever any source, asset or file-form font is present.
- The removed tests are recoverable at `154e474`, spread across three files: the monolithic-mode composition tests in `tests/test_block_engine.py` (~lines 2021–2054: tolerated name, emitted exactly once, document-level settings kept, first-page style suppressed, slot-source conflict), the `page_template_source` asset-resolution tests in `tests/test_renderer.py` (lines ~77–267; their current slot-source equivalents already exist and stay), and the autodetect/CLI tests in `tests/test_cli_page_template.py`. The current module helpers `tests/test_block_engine.py::_render_tex` (~line 1068) and `tests/test_renderer.py::_render_recipe_tex` (~line 491) forward only `header_source`/`footer_source` and need to forward the new argument. The current `tests/test_cli_page_template.py::test_a_sibling_template_file_is_not_picked_up` asserts the opposite of the reinstated behavior and gets replaced.
- `CLAUDE.md` and both READMEs state "there is no whole-page source" / document only the slot flags; the CHANGELOG's 0.17.0 entry records the removal (history — left as is).

### Provenance

- **User decision** (issue #85, conversation 2026-08-31): reinstate the whole-page form on `render()`, as a CLI flag, and with autodetection.
- **Agent judgment, open to question** (declared so in the issue): the composition details — the whole-page source owns both slots and suppresses the variant fragments; document-level settings keep applying. The design decisions below extend that judgment; D4 (server field) goes beyond what the issue asks for and is flagged for review.

### Design decisions

- **D1 — Composition model: reinstate the shared-source slot pair (agent judgment, matches the issue's presumption).** `SlotSpec` regains the `shared_source: bool` flag; `load_page_template()` regains the `page_template_source` keyword; when set, `header = SlotSpec(source=src)` and `footer = SlotSpec(source=src, shared_source=True)`, and the footer arm in `_page_template.tex.jinja` regains its `\BLOCK{if not page_template.footer.shared_source}` guard. Everything else falls out of the existing custom-slot machinery with no new branches: no header-space reclaim, no first-page plain style, no footer fragment or `\fancyfoot[C]{}`, and `_check_margin_top` skips it. The whole-page source owns the two *page-template slots*, not the document's content: a recipe's top-level `data.footer` is still emitted after the composition and wins, exactly as it does over a custom `footer_source` today.
- **D2 — Document-level settings apply in whole-page mode (user-endorsed direction in the issue).** `font`, `header_font`, `diff_style` and `margins` are read from `data.page_template` and emitted before the source, so the source's own `\geometry`/`\setmainfont` wins on conflict — identical to the slot-source behavior today. The payload's `header`/`footer` values are ignored *for composition* but remain schema-validated (validation runs before slot resolution), mirroring how `header_source` already shadows the payload's `header`. `first_page_header` is accepted but inert (custom header). `page_numbers` is inert for the page-template footer (custom) but still reaches a recipe-level `data.footer` through `emit_kxfooter` — kept, and locked by a test.
- **D3 — Mutual exclusion, enforced once in the loader (restore + centralize).** `load_page_template()` raises `ValueError` when `page_template_source` is combined with `header_source` or `footer_source` — one choke point that also covers direct calls to `prepare_block_context`/`prepare_recipe_context`, instead of re-checking in `render()`. On the CLI, `--page-template` combined with `--header-template`/`--footer-template` is a CLI error before rendering; on the server the core `ValueError` already maps to `400 input_error`. Autodetection is suppressed when any of the three flags is given (explicit `--page-template` wins over autodetect; slot flags suppress it entirely).
- **D4 — Server field (agent judgment, beyond the issue's ask — open to question).** Add an optional `page_template_source` field to `POST /render`: same size and encodability checks as the slot sources, counted in the `asset_dir` condition, forwarded to the core; the slot-conflict rejection comes from the core's `ValueError` → `400 input_error` mapping, no endpoint-side duplicate. Rationale: the issue notes klartex.se's bundle model is whole-page shaped and the migration story runs through this endpoint. Carries its own doc surface: the server module docstring, the request examples in both READMEs, and the HTTP-surface paragraph in `CLAUDE.md`. This decision lifts out cleanly into a follow-up issue if review prefers a smaller PR.
- **D5 — Parameter placement: keyword-only (agent judgment).** At `154e474`, `page_template_source` was the third positional parameter of `render()` and positional in the internal helpers. Reinstate it keyword-only, next to `header_source`/`footer_source`, on `render()`, `prepare_block_context()`, `prepare_recipe_context()` and the two `_render_*` helpers — the no-backward-compat rule means there is no call-site reason to preserve the old positional slot, and the three source parameters belong together.
- **D6 — Tests come back from history, adapted and placed by responsibility (agent judgment).** Start from the `154e474` versions of the removed tests and adapt them to the current payload shapes (no aliases, `fields` under slots), split as: `test_page_templates.py` — shared-source pair, `header_reclaim` empty, exclusion in the loader; `test_block_engine.py` — emitted exactly once, document-level settings kept (incl. the post-removal `margins`), first-page suppression; `test_renderer.py` — recipe-path forwarding, faktura `data.footer` + `page_numbers` precedence, one xelatex end-to-end render with a whole-page source overriding geometry and `\setmainfont` (the user's documented use); `test_cli_page_template.py` — autodetect units and CLI flows. Both `_render_tex`-style helpers gain the forwarding.
- **D7 — Autodetection requires a regular file (agent judgment, hardening over `154e474`).** The old helper used `.exists()`; a directory or broken symlink named `report.tex.jinja` would be "detected" and fail later in `read_text()`. Use `.is_file()` for both candidates.

### Out of scope

- Any bundled/named whole-page templates or a `read_page_template_source`-style composer for built-ins — nothing named it in the issue and the alias layer it hung off is gone.
- Jinja-rendering the custom source with data context — the source is inserted verbatim, as it always was.
- Changing recipe footer precedence or the `page_numbers` plumbing — existing behavior, kept and locked.
- CHANGELOG entry — written at release time per the release flow, not in the PR.

## Steps

1. **Slot model** — `klartex/page_templates.py`: add `shared_source: bool = False` to `SlotSpec` (with the "emitted once" doc comment); add keyword-only `page_template_source: str | None = None` to `load_page_template()`, raising `ValueError` when combined with a slot source (D3) and otherwise building the shared-source slot pair before the per-slot resolution (document-level settings resolved as usual first; payload `header`/`footer` not read in this mode). Update the module docstring's "custom sources travel as…" paragraph.
2. **Composition template** — `klartex/templates/_page_template.tex.jinja`: reinstate the `\BLOCK{if not page_template.footer.shared_source}` guard inside the footer custom arm, and mention the whole-page form in the header comment.
3. **Engine plumbing** — `klartex/block_engine.py::prepare_block_context` and `klartex/recipe.py::prepare_recipe_context`: accept keyword-only `page_template_source` and pass it to `load_page_template()` (docstrings included).
4. **Renderer** — `klartex/renderer.py::render`: add keyword-only `page_template_source`, thread it through `_render_block_engine` / `_render_recipe`, and extend the docstring (owning both slots; document-level keys still apply; cannot combine with slot sources — raised by the loader; raw text with no path, so API callers pass `asset_dir` themselves — the `154e474` docstring has the wording).
5. **CLI** — `klartex/cli.py`: restore `DEFAULT_PAGE_TEMPLATE_FILENAME`, `_autodetect_page_template()` (with `.is_file()`, D7), and the `--page-template` option — help text saying it owns both slots while `data.page_template`'s document-level settings still apply, and covering autodetection and asset resolution. Resolution order: explicit `--page-template` → sibling `<stem>.tex.jinja` → `./page_template.tex.jinja`; slot flags and `--page-template` are mutually exclusive; slot flags also suppress autodetection; any explicit or autodetected whole-page file sets `asset_dir` to its `.resolve()`d parent (symlink → target dir, matching the slot flags); autodetection prints `Using page template: <path>` to stderr; pass `page_template_source=` to `render()`.
6. **Server (D4)** — `klartex/server/render.py`: add `page_template_source` to `RenderRequest` (description mirroring the slot fields), run `_check_encodable` and `_check_source_size` on it, include it in the `asset_dir` condition, and pass it to the core `render()`. Update the module docstring's inline-sources sentence.
7. **Tests** — per D6:
   - `tests/test_cli_page_template.py`: the `_autodetect_page_template` unit tests from `154e474` plus a non-file candidate (directory named `page_template.tex.jinja`); explicit absolute/relative `--page-template`; autodetected sibling in a subdir and cwd default (asserting `asset_dir` and the stderr notice); `--page-template` vs slot-flag conflict; slot flags suppress autodetection; missing `--page-template` file error. Replace `test_a_sibling_template_file_is_not_picked_up` with its positive counterpart.
   - `tests/test_page_templates.py`: whole-page mode builds the shared-source pair; `header_reclaim` is empty; loader-level exclusion `ValueError`; payload `header`/`footer` ignored for composition.
   - `tests/test_block_engine.py`: source emitted exactly once in the composed preamble; `font`/`header_font`/`diff_style`/`margins` from the payload still emit; first-page style suppressed. `_render_tex` forwards `page_template_source`.
   - `tests/test_renderer.py`: recipe path forwards the source; faktura with a whole-page source + top-level `footer` still emits `\kxfooter` and honors `page_numbers`; xelatex end-to-end render with a geometry + `\setmainfont` override. `_render_recipe_tex` forwards `page_template_source`.
   - `tests/test_server.py` (D4): request with `page_template_source` renders; combined with a slot source → 400 `input_error`; oversized source → 400 like the slot fields; surrogate/encodability check covers the new field; the field alone flips `asset_dir` on (asset beside the request resolves).
8. **Docs** — update the page-template sections in `README.md` and `README.en.md` (CLI examples, "Egen sidmall"/custom-template section, asset-resolution notes, and — for D4 — the HTTP request example) and the `CLAUDE.md` paragraphs that currently state there is no whole-page source (Page templates section, custom-slot-sources paragraph, and the HTTP-surface section for D4). Written in now-state — the docs describe the capability, not its round trip through #80/#85.
9. **Full suite** — `pytest -rs -n auto`; confirm no xelatex-tagged or `test_server` test is skipped, and run the user-shaped smoke check: a data file with a sibling `<stem>.tex.jinja` renders from another cwd with its logo found beside the template.

## Risks

- **The footer-precedence matrix regressing silently.** The whole-page arm meets the recipe-level footer and the `page_numbers` plumbing. Mitigated by D1's shape — the whole-page form reuses the existing custom-slot arms rather than adding branches — and by the dedicated faktura precedence test in step 7.
- **Autodetection surprising a caller with a stray file.** `<stem>.tex.jinja` or `page_template.tex.jinja` sitting next to unrelated data silently changes the render. This is the designed (and explicitly requested) behavior, softened by the stderr notice; the conflict/suppression rules keep explicit flags authoritative, and D7 keeps non-files from tripping it.
- **Server scope (D4) drawing review pushback.** Flagged as beyond the issue's ask; step 6, its tests and its doc touches lift out into a follow-up issue without touching the rest if the user prefers.
- **Main is moving fast in this area.** #84/#89/#92/#93 all landed in `page_templates.py`/fragments since this issue was filed; the plan was verified against `main` at `24e81a6`. Re-verify the touched regions if implementation starts much later.

## Test Plan

- Fast unit level: autodetection resolution order, suppression and the non-file candidate; shared-source slot pair; single emission; document-level settings incl. `margins` in whole-page mode; recipe footer + `page_numbers` precedence; mutual-exclusion errors (loader `ValueError`, CLI exit + message, server 400).
- xelatex level: one end-to-end render with a whole-page source overriding geometry and `\setmainfont`; the asset-resolution CLI tests (plain-name and `./`-prefixed assets beside an autodetected/explicit template, from a different cwd).
- `pytest -rs -n auto` green with zero skips of xelatex-tagged or `test_server` tests.
